## What this session changed (all pushed, need deploy)

- **Web booking → payment page.** A card booking with any real (shown) price now goes
  straight to the payment page; it no longer required a fixed-matrix route. Quote/POA
  (no price) still goes to the office. Thank-you copy is payment-focused for card jobs.
- **Conversion tracking value.** The `cetBooking` postMessage now carries the whole
  job value (both legs of a return) and sends a separate `quote_request` event. The
  site runs **GTM (`GTM-WHH77L45`) + GA4** already — Google Ads conversion should be
  wired **in GTM** (no live-site file edit). Steps were given to the operator.
- **PVT email routing.** Non-VAT bookings must email from the PVT company. Admin
  bookings now **stamp `billing_entity`** at creation (non-VAT = `chauffeurs`), like the
  web widget, instead of recomputing it (which silently fell back to the main company
  when Stripe wasn't detected). PVT sending still requires **Settings → email → "Send
  PVT LTD emails" ON** + a PVT from-address + a PVT mailer (Resend key saved). NOTE:
  the Settings **test-email button bypasses** that toggle, so it passing does NOT prove
  the toggle is on.
- **Return bookings (admin form).**
  - Separate **return-leg addresses** (defaults to the reverse, editable); the return
    isn't always a straight reverse.
  - **Auto-reprices** the return leg from its own addresses (pricing endpoint +
    form JS now send `return_pickup`/`return_destination`).
  - **Fare split per leg** (£55 + £55, from the live quote's per-leg figures; same
    ratio when the office edits the total; else 50/50). Each leg stores its own fare.
  - **Two confirmations** (outbound …A, return …B), **both** carry a pay button that
    charges the **whole trip**; paying once settles both (failsafe: a part-payment can
    never mark both paid — see `BookingStatusService::onFarePaid`).
- **Email preview.** A "Preview email" button on the create form (pre-save, lenient,
  read-only) and on the booking page. Returns preview at the per-leg fare.
- **Mark paid now sends confirmations.** The main "Mark paid" button (`payments.paid`)
  and the transaction mark-paid paths now run `onFarePaid` → flip to paid + email the
  **customer the paid receipt + invoice** + the **office** the "payment received"
  notice. Idempotent. **Imported ETO/calendar customers are never auto-emailed**
  (`source_system` guard in `emailPaidConfirmation`).
- **Meet & greet = arrivals only.** The form treated the Airport dropdown (set for
  rotation) as "pickup is an airport," so a departure (e.g. Rotherham→Gatwick) wrongly
  ticked meet & greet. Direction now comes from which END is the airport.
- **Confirmation email completeness.** Added **Luggage** (suitcases + hand bags),
  **Child seats**, and **Notes** (special requests) to the email — they were missing.
